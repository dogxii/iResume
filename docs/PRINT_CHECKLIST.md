# 打印 / 导出 PDF 手工核对清单

自动化测试能覆盖的部分：

- **Chromium**：`e2e/pagination.e2e.ts` 用 8 套预设的长简历生成真实 PDF，核对页数与编辑器一致。
- **Firefox / WebKit**：CI 跑同一套功能测试（编辑、弹层、同步、修订标记、无障碍）。
  - 这两个引擎没有可自动化的 PDF 生成，打印结果只能人工看。
  - Playwright 的 WebKit 断网模拟不经过 Service Worker，离线用例只在 Chromium / Firefox 上跑。

发版前，或者改了 `src/render/resume.css`、`src/editor/measure.ts`、`src/editor/print.ts` 之后，在下面的浏览器里各走一遍。

## 准备

1. 首页导入 `e2e/helpers.ts` 里 `longDoc` 那样的两页简历：
   - 工作经历 8 条以上；
   - 每条 2–3 个要点，含加粗和链接。
2. 依次切换这几套预设：**清简**、**侧标题**、**双栏**、**时间线**。
3. 记下编辑器底部显示的页数。

## 每个浏览器都要看

| 项目 | 期望 |
| --- | --- |
| 页数 | 与编辑器显示的页数一致 |
| 纸张与页边距 | 选择 A4 / Letter 后，打印预览纸张尺寸正确，上下页边距与设置一致 |
| 区块标题 | 不会单独留在页尾。`break-after: avoid` 只有 Chromium 支持，其他浏览器靠编辑器算出的显式换页 |
| 条目 | 不会被拆到两页（比一整页还长的条目除外） |
| 双栏侧栏色带 | 通到最后一页底部 |
| 背景色 / 强调色 | 打印对话框里勾选「背景图形」后颜色正确 |
| 链接 | PDF 里可以点击 |
| 编辑器痕迹 | 没有工具条、批注、修订标记、占位符 |
| 文件名 | 默认文件名是简历名称 |

## 浏览器矩阵

| 浏览器 | 打印入口 | 已知差异 |
| --- | --- | --- |
| Chrome / Edge（最新） | 导出 → PDF → 另存为 PDF | 基准 |
| Firefox（最新） | 同上，目标选「保存为 PDF」 | 不支持 `break-after: avoid`，由显式换页兜底 |
| Safari 18.2+（macOS） | 同上，左下角「PDF → 存储为 PDF」 | 18.2 起支持 `@page` 的 size / margin。不支持 `break-after: avoid`，而且 `CSS.supports()` 会误报支持 |
| Safari（iOS / iPadOS） | 分享 → 打印 → 双指放大预览 → 分享 | `@page` 支持仍不稳定，可能忽略页边距；建议在桌面端导出 |

发现差异时，在 issue 里附上浏览器版本、所用预设和导出的 PDF。
